# VELNARO SEO, Search Console and Analytics Setup

## Production environment variables

Set these in the hosting provider for the **Production** deploy context, then trigger a fresh deploy:

| Variable | Value | Required |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | `https://velnaro.agency` | Yes |
| `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION` | The exact `content` token supplied by Google Search Console's HTML-tag method (token only, not the full meta tag) | For Search Console HTML-tag verification |
| `NEXT_PUBLIC_GA_ID` | Your GA4 Measurement ID, in the form `G-XXXXXXXXXX` | Optional; leave empty until GA4 is created and consent/privacy details are approved |
| `NEXT_PUBLIC_SUPABASE_URL` | Existing Supabase project URL | Yes, already used by the site |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Existing Supabase anon/public key | Yes, already used by the site |
| `SUPABASE_SERVICE_ROLE_KEY` | Existing Supabase service-role key | Yes, server-only; never expose or prefix with `NEXT_PUBLIC_` |

Do not replace or share the Supabase secrets while adding the two Google variables.

## Google Search Console

1. Open Google Search Console and add `https://velnaro.agency/` as a **URL-prefix property**.
2. Choose **HTML tag** verification.
3. Copy only the value inside the meta tag's `content="..."` attribute into `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION`.
4. Add the variable to the hosting provider and redeploy.
5. In Search Console, select **Verify**. The root layout emits the verification meta tag only when the variable is non-empty.
6. Submit `https://velnaro.agency/sitemap.xml` under **Sitemaps**.
7. Use **URL Inspection** for the homepage and key service pages, then request indexing where appropriate.

DNS verification is also valid and does not require the HTML-tag variable. Do not add a second verification method unless you need it.

## Google Analytics 4

1. Create a GA4 property and a Web data stream for `https://velnaro.agency`.
2. Copy the Measurement ID (format `G-XXXXXXXXXX`) into `NEXT_PUBLIC_GA_ID`.
3. Deploy the variable.
4. Analytics is not loaded until a visitor selects **Allow analytics**. Rejecting leaves the script unloaded. The choice is stored in local storage and can be changed with the **Privacy settings** control.
5. Verify accepted traffic using GA4 **Realtime** and Tag Assistant. Test both accept and reject paths in a private browser session.

The consent control is a technical opt-in implementation, not a legal compliance determination. Have the privacy/cookie wording and consent approach reviewed for the countries where the site is marketed. If analytics is not needed, leave `NEXT_PUBLIC_GA_ID` empty.

## Public discovery files

- `/robots.txt` is generated by Next.js. Public search/retrieval bots are allowed; private API/admin paths are disallowed. Training-oriented crawlers are explicitly disallowed by default.
- `/sitemap.xml` is generated by Next.js and lists canonical public routes only. A last-modified date is included only where a real content date is known; do not publish guessed dates.
- `/llms.txt` and `/llms-full.txt` describe the actual service pillars and clarify that Paid Growth and standalone CRO are not currently listed services.
- `/favicon.svg`, `/site.webmanifest`, the Next.js icon routes and `/opengraph-image` provide browser and social metadata assets.

## Important manual checks

- Confirm all URLs in the sitemap return HTTP 200 and canonical tags point to the same preferred HTTPS URL.
- Check Search Console Page indexing, Sitemaps and HTTPS reports after Google has crawled the site.
- Check GA4 only after explicit consent; compare reject and accept sessions.
- Keep the legal operator identity, business address and hosting/data-processing disclosures accurate in the privacy policy. These details are intentionally not fabricated in code.
